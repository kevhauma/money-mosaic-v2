# TICKET-SRV-01 — Express + SQLite + Drizzle backend skeleton

- **Area:** Server
- **Released in:** _unreleased_
- **Type:** Feature
- **Traceability:** new — introduces a backend, superseding the "no backend" premise in [`CLAUDE.md`](../../../CLAUDE.md) and **Persistence** in [`finance-app-spec.md`](../../reference/finance-app-spec.md); planned for v3

## User story

As someone self-hosting Money Mosaic on a machine in my own home, I want a small server with a SQLite database running behind the Angular app, so there is somewhere for multiple accounts and their data to live.

## Description

Stands up the backend process the rest of v3 builds on: an Express app, a SQLite file, and Drizzle ORM over `better-sqlite3`, wired so `ng serve` proxies `/api` to it during development. This ticket delivers **infrastructure only** — no users, no entity tables, no client changes beyond the dev proxy. Everything else in v3 depends on it.

## Current situation (as-is)

- There is no server. [`package.json`](../../../package.json) has no Express, SQLite, or ORM dependency, no `server/` directory exists, and `ng serve` is the only process the app has ever needed.
- All persistence is [`app-db.ts`](../../../src/app/core/data-access/app-db.ts)'s Dexie `AppDb` (db name `money-mosaic`, schema version 16), opened in `provideAppInitializer` in [`app.config.ts`](../../../src/app/app.config.ts) before render.
- `ng serve` runs on port 4210 (the `dev` preview launch config); there is no `proxy.conf.json`.
- The repo is a single Angular workspace — one `tsconfig`, one ESLint config, one Vitest setup, all scoped to `src/`.

## Desired result (to-be)

- A **`server/`** directory at the repo root with its own `package.json`, `tsconfig.json`, and ESLint config, kept out of the Angular workspace's `tsconfig`/lint/test globs so an Angular build never compiles server code and `ng lint` never reads it.
- Dependencies, pinned in `server/package.json` and **not** in the root one: `express`, `better-sqlite3`, `drizzle-orm`, and `drizzle-kit` + `tsx` (or equivalent) as dev dependencies. Nothing here reaches the browser bundle.
- **`server/src/index.ts`** boots an Express app on a configurable port (default **4300**, `PORT` env override), with `express.json()`, a request logger in dev, and a JSON error handler that turns a thrown error into a `{ error: string }` body rather than an HTML stack page.
- **`GET /api/health`** returns `{ ok: true, schemaVersion: <n> }` — the one endpoint this ticket ships, used by later tickets' smoke checks.
- **`server/src/db.ts`** opens `better-sqlite3` against `server/data/money-mosaic.sqlite` (path overridable via `DB_FILE`), enables `PRAGMA foreign_keys = ON` and `PRAGMA journal_mode = WAL`, and exports a single Drizzle instance. The directory is created on first boot if missing; `server/data/` is added to [`.gitignore`](../../../.gitignore).
- **Migrations** live in `server/drizzle/` and are generated by `drizzle-kit`. The server runs pending migrations on boot before it listens, so starting the process is the only step needed to get a usable database. The schema file this ticket creates is empty of entity tables — TICKET-SRV-02 fills it.
- **Scripts**, added to the root [`package.json`](../../../package.json): `server` (run the backend), `server:migrate` (generate/apply migrations), and `dev` (run `ng serve` and the server together). Running `ng serve` alone still works — it just gets connection errors from `/api` until the server is up, which is TICKET-SRV-06's problem, not this one.
- **`proxy.conf.json`** maps `/api` from the dev server to `http://localhost:4300`, wired through `angular.json`'s serve target, so the browser sees one origin and no CORS configuration is needed in development.
- **`server/` has its own Vitest setup** so backend tests run independently of `ng test`, with a root `test:server` script. Backend tests open an **in-memory** SQLite database, never `server/data/`.

## Acceptance criteria

- [ ] `npm run server` starts the process, creates `server/data/money-mosaic.sqlite` if absent, applies pending migrations, and serves `GET /api/health` with `{ ok: true }`.
- [ ] A second start against the existing file applies nothing and starts cleanly — migrations are idempotent.
- [ ] `PORT` and `DB_FILE` env overrides are honoured, covered by a test for the resolution of each.
- [ ] `PRAGMA foreign_keys` reads back `1` and `journal_mode` reads back `wal` on an opened database, asserted by a test.
- [ ] `npm run dev` brings up both processes, and a request to `http://localhost:4210/api/health` through the proxy reaches the server.
- [ ] `ng build --configuration development` and `ng lint` both succeed and neither one reads anything under `server/` — verified by a deliberate type error in a server file leaving both green.
- [ ] No server dependency appears in the root `package.json` `dependencies`, and `ng build` reports **no change** to the initial bundle. The `angular.json` budgets are **not** raised.
- [ ] `server/data/` is gitignored; no `.sqlite` file is ever committed.
- [ ] Backend tests run via `npm run test:server` against an in-memory database and cover: health response shape, migration idempotency, pragma state, env overrides.
- [ ] Verified via the fallow skill and coding-conventions skill.
- [ ] Verified live in the browser: with `npm run dev` running, the app loads as before and `/api/health` responds through the proxy.

## Notes

- **This ticket knowingly contradicts a founding constraint.** `CLAUDE.md` opens with "**No backend** — all data lives in IndexedDB". That line is not edited here: it stays true until the data actually moves, and [TICKET-SRV-08](./TICKET-SRV-08-retire-dexie.md) rewrites it as the last step of v3. Editing it now would make the repo's own documentation lie for the length of the version.
- **Port 4300** is chosen to sit clear of 4210 (`ng serve`) and 4200 (Angular's default) so a stray default-port serve cannot collide with the API.
- `better-sqlite3` is a native module, so `npm install` compiles or downloads a prebuilt binary. This is a local-hosting project, so that cost is paid once on the machine that hosts it — worth knowing before it surprises someone on a fresh clone.
- Deliberately **not** in scope: users, auth, entity tables, serving the built Angular app from Express (that is [TICKET-SRV-09](./TICKET-SRV-09-single-process-local-hosting.md)), and any Docker/systemd packaging.
